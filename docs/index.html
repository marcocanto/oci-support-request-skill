The workflow

A small, evidence-backed support package.

The skill keeps collection, preparation, and submission separate so each stage is easy to inspect.

1

Describe the issue

Provide the service, symptom, region, UTC window, resource OCIDs, error, and impact.

2

Preview the plan

Review the selected read-only commands and see which required inputs are still missing.

3

Collect and sanitize

Run the approved evidence plan and redact common secret, token, tag, and metadata fields.

4

Build the SR

Generate a concise description, evidence manifest, attachments, and optional CLI payload.

5

Approve and verify

Preview every write, approve it explicitly, and read the SR back to verify the result.

Safety model

          
Read freely. Write deliberately.

          
The skill treats evidence gathering and Support Management as two different trust boundaries.

        


        

          

            
● Read-only collection

            
    
              
  • Resource GET and LIST operations
    • 
              
  • Narrow Audit event windows
    • 
              
  • Resource-filtered Monitoring queries
    • 
              
  • Current service limit values
    • 
              
  • Plan mode before execution
    • 
            

          


          

            
◆ Explicit approval required

            
    
              
  • Create a support request
    • 
              
  • Add a customer-visible comment
    • 
              
  • Upload each reviewed attachment
    • 
              
  • Add or change a contact
    • 
              
  • Update or close an SR

What you receive

          
Small artifacts that shorten triage.

          
The default output is designed to be reviewed quickly and attached selectively.

        


        

          

            TXT
            
SR Description

            
A paste-ready problem statement with impact, timing, resources, errors, and troubleshooting.

          

          

            JSON
            
Evidence files

            
Sanitized outputs from the focused OCI CLI commands that completed successfully.

          

          

            JSON
            
Manifest

            
Commands attempted, UTC execution times, skipped checks, missing inputs, and failures.

          

          

            JSON
            
SR payload

            
An optional validated TECH request body that remains local until submission is approved.
